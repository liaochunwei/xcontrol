# 跨设备文件复制粘贴（粘贴时才传输）

> 父任务：持有需求源、任务地图与跨子任务验收。实现工作全部在子任务进行。

## Goal

让跨设备文件复制**像本地操作一样**：在 A 机复制文件，B 机粘贴时文件才真正传输。
复制瞬间只同步元数据清单（几 KB），内容字节完全由接收端的粘贴动作触发拉流。

对应需求域：FR-7.3（新增，规范子任务落 docs/00）；现状是 FR-4.6 仅路径文本、
FR-7.1/7.2 延后池"复用 v1 分块传输通道"的预留方向（docs/00 §4.7、docs/09 延后池）。

## 用户故事

| # | 故事 |
| --- | --- |
| US-FT-1 | 我在 Mac 的 Finder 复制 3 个文件（128MB），切到 Windows 从机上在资源管理器里 Ctrl+V，文件出现在粘贴目标；粘贴前无大流量。 |
| US-FT-2 | 我复制后立即在托盘看到「剪贴板文件：3 项 / 128 MB（来自 Mac）」提示，知道有什么可贴。 |
| US-FT-3 | 粘贴时源机已离线/文件已被删除 → 我收到明确错误提示，连接与输入不受任何影响。 |
| US-FT-4 | 我复制一个目录 → 对端粘贴还原整棵目录树。 |

## Requirements（跨子任务分解）

- **R-SPEC 规范先行**（子任务 `11-26-file-transfer-spec`）：ADR-0004 + docs/00/02/04/05/07 修订。协议红线：先文档后代码。
- **R-A 元数据面**（`11-26-file-ref-announce`）：复制端四平台检测文件引用剪贴板 → `FileRefAnnounce` 元数据清单 → 对端 pending 槽 + 托盘指示；代次失效与防回环。
- **R-B 传输面**（`11-26-file-channel-pull`）：独立文件 TCP 通道；条目索引拉流（`FilePullReq/Chunk/Ack/End/Error`）；落盘暂存；托盘显式「传输并粘贴」动作端到端可用。
- **R-C 透明粘贴**（`11-26-paste-materialize`）：注入路径拦截粘贴键，pending 槽有货时先物化挂板再注入。
- **R-D 完善**（`11-26-file-transfer-polish`）：目录清单（顶层先行）、进度 UI、blake3 校验、部分成功策略。

## 跨子任务验收标准（父任务整合验收）

- [ ] 全链路：mac 复制 → win 粘贴、win 复制 → mac 粘贴，粘贴前抓包无大流量（元数据 < 16KiB）。
- [ ] 文件通道任何故障（超时/违规/断连）不影响控制连接与剪贴板同步（复用 §4.4 双连接隔离语义）。
- [ ] 拉取请求只含条目索引，无路径字段（docs/07 安全面红线）。
- [ ] 防回环：A 复制 → B 物化 → B 的监听器不把物化挂板当新复制回传（新指纹规范形生效）。
- [ ] 协议 golden fixtures 同步新增（docs/02 §8 要求）。

## 非目标（父任务）

- 不做 OS 原生惰性粘贴（mac file promise / win CFSTR_FILEDESCRIPTOR）——列为后续增强，v1 统一「落盘后挂板」。
- 不做拖放传文件（FR-7.2 另立）、不做共享文件夹（FR-7.1 另立）。
- 不做公网/中继场景（沿用 docs/00 §6.1）。
