# 修复热键切入后边缘回切失效与快速过边停滞

## Goal

让"切换控制权"在边缘路径与热键/托盘路径上语义一致、手感连续：

1. 热键切入工作机后，把光标推回**面向主控的那条边**即可回切（与边缘切入后的行为一致）。当前无效，只能再用热键。
2. 快速甩动鼠标过切换边时不再有"撞边停住 / 过边后回跳"的停滞感；慢速移动的现有手感不变。
3. 热键回主控时，光标停在受控期间所见的位置（切入锚点），不再跳到屏幕中央。
4. 主控与工作机的四个角落区域内都不触发切换，角落留给系统热角使用；角落区外的边照常切换。

对应需求：FR-2.1（光标跨屏）、FR-2.2（从机边缘反向移动回到主控）、FR-2.5（热键切换）。

## Background（已确认事实）

用户报告的症状与后续追加的诉求，经代码走读与项目自身的实机记录（docs/05 §1.2）定位到八个成因。行号为任务创建时的代码位置。

- **C1 热键路径回切边取反**。`SwitchAck` 接管分支把回切触发边设为"进入边的对侧"（远离主控的边）：`crates/xcontrol-core/src/session.rs:1138`。11-22 把回切语义改判为"受控屏面向主控的边"（docs/03 §5 双向边缘回切第 5 条）后，边缘路径已跟随（同文件 `:1295`，`opposite_edge(主控滑出边)` 恰为进入边），热键路径漏改。现有测试只覆盖边缘路径。
- **C2 uinput 位置模型脱节**。uinput 后端的受控光标回报取自注入器维护的"虚拟位置"（`crates/xcontrol-input/src/platform/wayland.rs:589`），而 `release_all` 把它复位到屏幕中心（`:572`）。热键切换先到 `SwitchRequest` 并产出 `ReleaseAll`（`session.rs:1109`，经 `route.rs:196` 透传到 sink），随后的 `EnterScreen{preserve_cursor=1}` 不做 warp，于是虚拟位置与真实光标对不上，回切判定基于一个虚构位置。mac / X11 后端读真实光标，不受影响。
- **C3 切换检测延迟**。主控边缘轮询（`crates/xcontrol-app/src/edge.rs:59`）与工作机受控光标回报（`crates/xcontrol-app/src/session_rt.rs:1340`）都是 50ms 节拍：光标撞边后最坏要等 50–60ms 才切换。快速移动表现为撞边冻住，慢速移动不可感知。
- **C4 受控期间主控误触发**。边缘命中门控对 `LocalControlsPeer` 放行（`session_rt.rs:2164`）。docs/05 §1.2 的实测记录显示 macOS 26 非前台进程无法隐藏或解关联光标，只能每 10ms 把光标 warp 回锚点；快速移动时光标在两次回拉之间会冲到屏边，被传感器命中后重复发出 `EdgeCrossing`，工作机光标被拉回进入点、按键被释放、回切免疫窗被重置。
- **C5 回主控落点假设屏 0**。热键回主控的落点写死 `screen: 0`（`session.rs:1340-1344`），而显示器枚举序不保证主屏在前（`crates/xcontrol-input/src/platform/macos.rs:175`）。仅影响主屏不在枚举首位的 macOS 多屏主控。R4 改走切入锚点后，macOS 上这条落点路径不再执行。
- **C6 热键回主控落点跳到屏幕中央**。同一处落点固定为 `(0.5, 0.6)`，而受控期间用户看到的光标一直停在切入锚点上（C4 的锚定回拉），回主控瞬间会从锚点跳到屏幕中央。锚点保存在捕获源里（`macos.rs:947`）但没有对外访问器；文档从未规定过回主控的落点（docs/03 §4.6 只写了 `ReleaseControl` 的释放序列）。

- **C7 角落排除范围过小**。两侧的"角落区"都定义为两条边的容差带相交：主控切入 `edge_crossing`（`crates/xcontrol-core/src/layout.rs:128`）以归一化坐标两轴同时到端点为准，传感器容差带 ±1 点（`edge.rs:66`）；工作机回切 `at_orthogonal_extreme`（`session.rs:1725`）以正交轴回报恰为端点为准，回报容差带 ±1 像素或点。每个角落因此只有约 1 点见方，光标斜着进角落几乎必然先在角落外贴到可切换的边。现有测试钉死了这一行为（`layout.rs:551`、`edge.rs:687-691` 断言离角 1.5 个点即触发）。
- **C8 边缘回切时行程丢失**（用户 2026-11-24 实机反馈后定位）。三段位移在回切时没有任何渠道保留：工作机光标顶边期间被屏幕边界截掉的推进量（回报坐标被钳在端点值，`wayland.rs` 的 `cursor_normalized`）；回切触发后到主控恢复本地输入之间被丢弃的位移（翻拍要等下一个输入拍，`session_rt.rs` 收帧分支与输入拍）；主控最后转发的一批在工作机采样之后才到，没算进触发回切的回报。慢速移动时合计只有几像素，快速甩动时是几十到上百点，所以只在快的时候可感知。详见 research §8。

**关键耦合：C3 与 C4 必须同一次修。** 边缘轮询提到 10ms 后会与锚定回拉近乎同相位，受控期间的误触发概率反而上升；单改任何一个都会让体验变差。

## Requirements

- **R1 热键/托盘切入后的回切触发边 = 受控屏面向主控的边**（FR-2.2 / FR-2.5；修 C1）。与边缘路径一致；无布局时的回退也一致（受控屏左缘）。
- **R2 保持原位切入后，被控端的位置模型与真实光标一致**（FR-2.2；修 C2）。
  - 位置模型为虚拟的后端（uinput）：把"切出时的位置"保留为校准源，切入瞬间真实光标校准到该位置。
  - 位置模型即真实光标的后端（mac / X11 / mock）：行为不变。
  - 用户可见行为（Linux/uinput 工作机）：热键切入瞬间光标落到上次受控结束的位置，进程启动后首次为屏幕中心。与 docs/02 §4.2 对 `preserve_cursor` 的定义"光标留在切出时的位置"一致。
- **R3 受控期间主控边缘命中不触发切换；控制关系变化后 150ms 防抖**（FR-2.1；修 C4，并落地 docs/03 §5 已写明但未实现的死区条款）。
  - 受控期间主控光标被锚定，不存在有意滑边，命中一律忽略。
  - 控制关系任意变化沿之后 150ms 内忽略切入，防止回切落点贴缘时快速甩动造成的回弹。
- **R4 热键回主控的落点 = 切入锚点**（FR-2.5；修 C6，用户 2026-11-24 决定纳入）。macOS 主控在受控期间把光标锚定在切入处，回主控即原地解冻，不论当初是边缘切入还是热键切入；锚点不可得时不做落点定位，光标随物理鼠标。其余平台主控行为不变。
- **R5 切换检测与回切回报节拍不超过 10ms；回切免疫窗按时间计**（FR-2.1 / FR-2.2 体验；修 C3）。最坏切换延迟从约 50–60ms 降到约 10ms；免疫窗语义保持"接管后约 800ms"，不再随回报频率变化。
- **R7 主控与工作机的四个角落区域内不触发切换**（FR-2.1 / FR-2.2；修 C7；用户 2026-11-24 提出）。切入与回切两个判定面对称：光标在任一屏任一角落的角落区内贴边，不切入也不回切，区域外贴边照常触发。角落区 = 每屏四角、沿屏宽与屏高各取 5% 的矩形（用户选定；4K 约 192×108px，Mac 约 76×49pt）。单位取比例而非固定像素，是因为主控判定工作机回切时只有归一化坐标，不知道工作机分辨率。
- **R8 边缘回切时丢失的行程得到补偿**（FR-2.2 体验；修 C8；用户 2026-11-24 实机反馈后纳入）。工作机光标顶在屏边期间被屏幕边界截掉的位移，以及回切触发后到主控恢复本地输入之间被丢弃的位移，都要加到主控的回切落点上，使快速甩动回切后光标落点与手势连续。
- **R9 未授权辅助功能时弹系统引导，授权后自动恢复**（macOS；用户 2026-11-24 提出）。应用启动时若未授权，弹出系统的辅助功能引导框；主控在授权后自动重建捕获源，不需要重启应用或重建会话。现状是弹框能力已有但无人调用，捕获源创建失败只记一条日志。
- **R10 应用有图标**（macOS 打包；用户 2026-11-24 提出）。`.app` 带应用图标，Finder 与 Dock 不再显示系统默认空白图标。图形与托盘图标同源（环形加中心点、品牌蓝）。
- **R11 回切行程补偿平滑回放**（FR-2.2 体验；用户 2026-11-25 实机反馈后提出）。补偿量不再一次性加到落点上（快速移动时表现为直接跳跃）。光标先落在贴缘的未补偿位置，补偿量在几十毫秒内分步补回，最终落点不变。
- **R6 文档与规则卡同步**。docs/03 §4.6 与 §5、docs/05 §1.2 与 §4.5、CHANGELOG（Unreleased）、`.trellis/spec` 的 rust-core 与 rust-platform 规则卡。**无协议报文变更**（docs/02 的 wire 定义不动）。

## Acceptance Criteria

- [x] **AC1（R1）** core 单测：`[主控 | 工作机]` 布局经 `Switch` + `SwitchAck` 接管后，面向主控边（工作机左缘）的极值回报加同向移动触发回切，落点为主控右缘内侧 0.5%；远离主控边（工作机右缘）的极值回报不触发。该用例在修复前失败。
- [x] **AC2（R2）** core/app 单测：识别"保持原位切入"（产出 `EnteredControl` 且无 `WarpPointer`）并触发一次位置模型校准；边缘切入（含 `WarpPointer`）不触发。`InputSink` 新钩子默认无操作，两层包装 sink 透传。
- [x] **AC3（R2）** Linux 实机（uinput 工作机）：热键切入后光标位于上次受控结束的位置；朝主控方向推边可回切。（用户 2026-11-24 实机确认。）
- [x] **AC4（R3）** app 单测：门控真值表中 `LocalControlsPeer` 被拒绝；控制关系变化后 150ms 内的命中被拒绝、之后放行。
- [x] **AC5（R4）** app 单测：macOS 主控上热键回主控的动作序列剥离 core 的落点 warp，替代落点为切入锚点；无锚点时替代落点为空（不做落点定位）。
- [x] **AC6（R5）** core 单测：接管后 799ms 的极值回报不触发，800ms 起可触发；节拍常量为 10ms。现有回切用例（角落排除、按键门控、落点换算）全部保持通过。
- [x] **AC7** 实机（mac 主控 + Linux 工作机）：快速甩动过边无明显撞边停顿；切入后朝工作机方向继续快速移动，工作机光标不回跳、按键不丢；慢速切入不回弹；热键切入后推回面向主控的边可回切；热键回主控后光标停在受控期间所见位置。（用户 2026-11-24 实机反馈：除"快速甩动回切仍卡顿"外均通过；该项由 R8 承接，最终随 AC13 通过。）

- [x] **AC9（R7）** core/app 单测：四角区域内贴边不触发切入也不触发回切，区域外贴边照常触发；主控传感器判定与 core 两处判定使用同一角落比例。实机：把光标斜推进主控与工作机的四个角，不发生切换。（单测与实机均已验证：用户 2026-11-24 实机确认。）

## Out of Scope

- macOS 主控光标冻结机制本身（锚定回拉的可见抖动、朝切入方向猛推时的增量行为）。需要实机探针实验，禁止凭推断改平台行为。
- 捕获 tap 被系统禁用（`TapDisabledBy*`）后不自动重启。已知限制（`macos.rs:41`），单列任务。
- 多工作机并发与热键循环切换（当前单会话串行、Next 恒指向首台）、多屏工作机的多显示器寻址。
- 切入方向（主控到工作机）的同类行程补偿：主控光标顶在本机屏边时，物理位移能否从捕获流观测到属未验证假设，本次不动。
- macOS 与 X11 工作机的行程度量：这两种后端不度量，回报仍为端点值，回切落点没有补偿。
- 两端共用同一个写死的 `instance_id`（`main.rs` 的 `DEMO_INSTANCE_UUID`）：既有缺陷，uinput 后端不受影响，建议单列任务。
- 非 macOS 主控上"回主控落点假设屏 0"的修正。这些平台的边缘轮询尚未实装，主屏下标无从取得。
- 协议报文变更。
