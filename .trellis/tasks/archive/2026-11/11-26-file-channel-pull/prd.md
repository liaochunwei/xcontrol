# 切片b：文件通道拉流与显式传输粘贴

> 父任务：11-26-file-transfer；依赖切片 a（数据面）与 docs/02 §4.6 文件通道规范。

## Goal

独立第三条 TCP 文件通道 + 条目索引拉流 + 落盘暂存 + 托盘显式「传输并粘贴」动作，
端到端可用（不依赖粘贴拦截，切片 c 再做透明路径）。

## Requirements（开工时细化）

- R1 文件通道：另拨 TCP → Noise 握手 → FileBind{session_id}（ChannelBind 同款校验）；按需建立、空闲关闭；故障只影响文件域（独立重连退避）。
- R2 拉流状态机（core，平台无关）：FilePullReq(索引,offset) → FileChunk*(65472B 有效分块、信用窗口) → FileEnd(blake3 边流边算)；分块空闲超时 + 总时长上限。
- R3 源端文件服务：按清单条目打开/流式读取；拉取时 re-stat（文件消失/变小 → 条目级 FileError）；**只按已通告清单条目服务**（任意读红线）。
- R4 接收端暂存：专用暂存目录、剩余空间预检、超阈值需确认（docs/07）；完成后挂真实文件引用到系统剪贴板（四平台写路径，docs/05 矩阵）。
- R5 托盘「传输并粘贴」动作：暂存完成即注入粘贴（复用切片 c 之前的临时路径：直接注入粘贴键或用户手动 Ctrl+V，开工时定）。

## Acceptance Criteria（开工时细化）

- [x] 单机端到端（真 TCP + Noise + 真实磁盘，2026-11-26 集成测试实证）：
      发布真实临时文件 → 通告 → 拉取 → chunk/end 回传 → 暂存逐字节一致 →
      blake3 校验 → 挂板指纹登记。**双机实测（mac ↔ win/linux）移交人工**：
      托盘「接收文件」动作已实装（pending 投影 + 整单拉取队列），对端平台
      面按下条限制。
- [x] 故障注入：条目级软失败（哈希不符/源文件消失/空闲超时——core 单测 +
      集成测试断言控制与剪贴板连接不受影响、可重试语义）。
- [x] fuzz/fixtures：文件域九消息 golden fixtures（切片 a 已入库 26→35）；
      越界索引/伪造 transfer_id = 协议违规断开（file_serve 单测矩阵）；
      cargo-fuzz 实跑移交（同既有 fuzz 定时化池）。
- [x] 质量门全绿（clippy 双 feature 配置零警告、fmt、workspace 无 feature
      与 macos feature 测试全绿、check-deps PASS）。
