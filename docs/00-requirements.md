# 00 · 需求分析

> 状态：草案 v0.1 · 本文是所有其他规范的上游，功能范围以本文为准。

## 1. 背景与问题

多电脑工作场景（如 MacBook + Windows 台式机 + Linux 工作站）下，用户需要：

1. 在多台机器间频繁切换物理键鼠，或使用 KVM 硬件切换器；
2. 在机器间搬运文本/图片（聊天工具传文件、网盘、U 盘）；
3. macOS 与 Windows/Linux 的修饰键布局不同（`Cmd` vs `Ctrl`），肌肉记忆割裂。

现有方案的不足：

| 方案 | 不足 |
| --- | --- |
| Synergy（商业） | 收费、闭源、macOS 新版本权限适配滞后 |
| Deskflow（Synergy/Barrier 社区续作，本项目直接对标） | C++ 技术栈、Wayland 支持不完整、UI 老旧、默认无加密 |
| Barrier / Input-Leap | 同为 C++ 系；Input-Leap 仓库已于 2026 年归档，社区合流至 Deskflow |
| 硬件 KVM | 额外硬件、无剪贴板同步、无按键映射 |
| Logitech Flow 等 | 绑定特定硬件、最多 3 台 |

## 2. 产品目标

用 Rust 实现一个**局域网**内的键鼠共享 + 剪贴板同步 + 按键映射工具：

- 一个二进制，主控/从机两种角色可切换；
- 系统托盘常驻，低资源占用；
- 内建加密与自动发现，开箱即用（输一个安全码即可配对）；
- 原生支持 macOS / Windows / Linux X11 / Linux Wayland；
- UI 使用 gpui，风格现代、跨平台一致。

## 3. 用户故事

| # | 用户故事 |
| --- | --- |
| US-1 | 作为多电脑用户，我把光标移到主控屏幕右边缘，光标就出现在右侧从机屏幕上，键盘输入也切换到那台机器，移回左边缘即回到主控。 |
| US-2 | 作为多电脑用户，我在从机上复制一段文字/一张截图，回到主控（或另一台从机）直接粘贴，内容一致。 |
| US-3 | 作为 Mac + Windows 用户，我在主控 Mac 上按下 `Cmd+C`，Windows 从机上实际执行 `Ctrl+C`；所有 `Cmd` 快捷键可按规则映射。 |
| US-4 | 作为用户，我在任意一台机器上按下全局热键（可配置，默认如 `Ctrl+Alt+→`），控制权切换到下一台机器，无需移动光标到屏幕边缘。 |
| US-5 | 作为用户，我在从机上启动 XControl 并输入安全码，它自动找到同网段内使用相同安全码的主控机并连接；断网后自动重连。 |
| US-6 | 作为用户，我可以在设置中指定允许的网段（如 `192.168.1.0/24`），XControl 只在该网段内发现与接受连接。 |
| US-7 | 作为用户，我可以从托盘菜单暂停/恢复共享（临时把键鼠锁回本机）、切换主控/从机角色、退出程序。 |
| US-8 | 作为用户，我第一次运行时，XControl 引导我授予必要的系统权限（macOS 辅助功能、Linux uinput 组等）。 |

## 4. 功能需求

需求编号规则：`FR-<域>.<序号>`。每条带验收标准（AC）。优先级：P0 = v0.1 必须，P1 = v0.2，P2 = v1.0。

### 4.1 角色与连接

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FR-1.1 | P0 | 单一二进制支持主控/从机两种角色，可托盘切换、CLI 参数指定 | `xcontrol --role host|client` 启动对应角色；托盘菜单切换后 1s 内生效 |
| FR-1.2 | P0 | 一台主控可同时管理多台从机（上限 ≥ 8 台） | 8 台从机同时在线，事件路由无串扰 |
| FR-1.3 | P1 | 从机屏幕的相对布局可配置（相对某屏幕的 上/下/左/右，形成网格） | 设置窗口可视化编辑布局；跨屏切换方向与布局一致 |
| FR-1.4 | P0 | 主从通过安全码 + 网段配置相互认证 | 安全码不匹配的连接在握手阶段被拒绝并记录日志 |
| FR-1.5 | P1 | 同一进程一次只扮演一种角色；同机互连（自回环调试模式）可用 `--loopback` 开启 | 回环模式下本机既是主控又是从机，用于无第二台设备的开发调试 |

### 4.2 输入共享

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FR-2.1 | P0 | 光标跨屏：光标到达主控屏幕边缘且该方向存在从机屏幕时，控制权切换到该从机，光标出现在从机对应边缘位置（保持相对坐标） | 跨屏移动无可见跳动（< 1 帧错位）；无从机的边缘不切换 |
| FR-2.2 | P0 | 从机屏幕边缘反向移动可回到主控或进入相邻从机 | 从任意从机边缘移出，按布局进入相邻屏幕 |
| FR-2.3 | P0 | 键盘事件转发：按下/释放/长按重复、修饰键状态机、Unicode 字符直发（对从机无法模拟的组合） | 在从机打字无错漏（≥1000 字符连续输入测试）；修饰键组合（如 `Shift+A`）行为正确 |
| FR-2.4 | P0 | 鼠标事件转发：相对/绝对移动、垂直+水平滚轮、左/中/右/侧键、拖拽（按住移动） | 从机上可完成拖拽操作；滚轮方向与主控一致 |
| FR-2.5 | P0 | 全局热键切换：循环切换（下一台/上一台）、直接切回主控；热键可配置，含"切到指定从机"（P1） | 热键在主控与从机两侧都可用；热键本身不被转发到从机 |
| FR-2.6 | P0 | 键盘转发基于语义键码（scancode 抽象层），主控键盘布局（如 Dvorak、输入法开启）不影响从机输出 | 主控切换键盘布局后，从机输出字符不变 |
| FR-2.7 | P1 | 指针移动可选"绝对坐标映射"（主从屏幕分辨率不同也能对应位置） | 4K 主控 → 1080p 从机，光标相对位置一致 |
| FR-2.8 | P1 | 主控可临时"锁屏边界"（托盘一键），光标不再跨屏 | 切换后光标停留在主控边缘内 |

### 4.3 按键映射

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FR-3.1 | P0 | 从机侧可配置修饰键映射表（如主控 `Cmd` → 从机 `Ctrl`） | 在从机映射后，主控按 `Cmd+C`，从机收到 `Ctrl+C` |
| FR-3.2 | P0 | 内置平台预设：mac→win、mac→linux、win→mac、linux→mac 等；预设可被自定义规则覆盖 | 选择预设即生效，无需手写规则 |
| FR-3.3 | P1 | 支持普通键重映射（如 CapsLock → Esc）与整组快捷键映射（如 `Cmd+Shift+4` → `Win+Shift+S`） | 规则按"修饰键集合 + 键"精确匹配 |
| FR-3.4 | P0 | 映射只作用于"转发到从机"的事件，不改变主控本地输入 | 主控本地 `Cmd` 行为不受从机映射影响 |
| FR-3.5 | P2 | 映射规则支持按应用粒度（从机前台应用不同用不同映射） | 切换前台应用后映射规则随之切换 |
| FR-3.6 | P1 | 提供"直通模式"开关（关闭所有映射） | 托盘/热键一键切换 |

### 4.4 剪贴板同步

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FR-4.1 | P0 | UTF-8 纯文本同步 | 双向即时（复制后 < 200ms 可粘贴）；空剪贴板/超时处理正确 |
| FR-4.2 | P1 | 图片同步（PNG 作为交换格式） | mac 截图 → win 粘贴成功；win截图 → mac 成功 |
| FR-4.3 | P2 | HTML 富文本同步（尽力而为，降级为纯文本） | 带格式复制粘贴后格式保留或干净降级 |
| FR-4.4 | P0 | 同步范围可配置：仅主控 ↔ 当前受控从机（默认）/ 主控 ↔ 全部从机 | 配置生效；回环风暴（两台机器互相触发变化）被抑制 |
| FR-4.5 | P0 | 大小上限可配置（默认 16 MiB），超限不同步并托盘提示 | 复制 100MB 文本不导致卡顿或断连 |
| FR-4.6 | P2 | 文件路径列表同步（仅路径文本，不做文件传输） | 未开启时明确不提示 |
| 非目标 | — | 文件内容传输、拖放传文件（见 §6） | — |

### 4.5 发现与连接

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FR-5.1 | P0 | 从机未连接时自动扫描配置网段（默认全部接口所在网段）内安全码匹配的主控 | 输入安全码后 ≤ 5s 内连上同网段主控 |
| FR-5.2 | P0 | 三种连接方式并存：自动发现（UDP 广播探测 + mDNS）、手动指定 IP:端口 | 任一方式均可建立会话 |
| FR-5.3 | P0 | 断线自动重连：指数退避（3s 起，上限 30s；11-21 实测定稿：1s 重连与对端会话 teardown 重叠致帧交织），网络恢复后 ≤ 10s 重连 | 拔网线 30s 再插回，自动恢复 |
| FR-5.4 | P1 | 主控侧可开启"仅接受配置网段"与设备白名单（按首次连接指纹确认） | 网段外来源的连接被拒绝并记录 |
| FR-5.5 | P1 | 多个主控同安全码同网段时，从机列出候选让用户选择，可记住选择 | 选择后优先连接记住的主控 |

### 4.6 UI / 托盘

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FR-6.1 | P0 | 托盘常驻：图标反映状态（主控-N台在线 / 从机-已连接 / 从机-搜索中 / 已暂停 / 出错），悬停提示，菜单含：切换角色、暂停/恢复、打开设置、开机自启、退出 | 状态变化 ≤ 1s 反映到图标 |
| FR-6.2 | P0 | 设置窗口（gpui）：角色、安全码（掩码显示）、网段、连接列表、屏幕布局编辑器、按键映射编辑器、热键配置、日志级别、关于 | 所有设置持久化（TOML），修改即存 |
| FR-6.3 | P0 | 首次运行向导：角色选择 → 安全码 → 权限引导（按平台显示所需权限与跳转） | 每平台权限缺失时托盘给出可操作的提示 |
| FR-6.4 | P1 | 无 UI 模式：`--headless` 以从机模式运行（服务器/Linux 无桌面场景），配置走配置文件 | 无窗口进程稳定运行 |
| FR-6.5 | P2 | UI 多语言（中文/英文） | 切换语言即时生效 |

### 4.7 扩展功能（v0.2+ 规划，v1 仅预留扩展点，不在验收范围）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| FR-7.1 | 共享文件夹：主从间挂载指定目录，另一侧可浏览/读写（或以"网络盘"形式暴露） | v1 的分块传输通道（剪贴板大块数据复用）与消息类型空间为其预留；实现方式（内置文件服务/FUSE/系统共享）届时以 ADR 决定。功能对标 Deskflow 的方向延伸 |
| FR-7.2 | 拖放文件：把文件从一台机器拖到另一台屏幕边缘即传输 | 复用 FR-7.1 的传输通道 |

## 5. 非功能需求

| 编号 | 需求 | 度量 |
| --- | --- | --- |
| NFR-1 | 输入延迟低 | 局域网内端到端（主控按键 → 从机注入）：P50 < 15ms，P99 < 40ms（基准测试工具内建） |
| NFR-2 | 资源占用低 | 空闲时 CPU < 1%，RSS < 80MB（含 UI 进程）；从机 headless RSS < 30MB |
| NFR-3 | 传输安全 | 全流量加密（PSK 派生密钥），防重放；安全码不以明文存储、不以明文出现在任何报文中 |
| NFR-4 | 平台兼容 | **UI 完整体验**：macOS 15+（gpui-kit 运行时约束）、Windows 10 22H2+、主流 Linux（X11 与 Wayland：GNOME/KDE/wlroots 系）；**headless 从机**放宽至 macOS 13+ / 任意近代 Linux（不依赖 gpui） |
| NFR-5 | 故障隔离 | 从机崩溃/掉线不影响主控本机输入；主控退出时从机 3s 内回到本地控制状态 |
| NFR-6 | 可测试性 | 协议、路由、映射、布局等核心逻辑 100% 平台无关，可用 mock 平台层做单元/回环测试 |
| NFR-7 | 冷启动快 | 托盘可用 < 2s；连接建立 < 1s（发现完成后） |
| NFR-8 | 可观测性 | 结构化日志（tracing），连接/延迟/错误计数暴露为 `--status` 输出与日志 |
| NFR-9 | 可扩展性 | 协议消息类型空间 ≥ 25% 保留给扩展（文件传输/共享文件夹 FR-7.x）；剪贴板分块传输通道可复用于任意大块数据流 |

## 6. 非目标（v1.x 不做）

1. **公网穿透 / 中继**：仅局域网或用户自组 VPN 网段；
2. **远程桌面画面**：不传输屏幕画面（仅输入事件与剪贴板），不做远端显示；
3. **文件传输 / 共享文件夹**：v1 不做文件内容的网络传输与拖放传输（规划于 FR-7.1/7.2，协议已预留扩展点）；
4. **移动平台**：不支持 iOS/Android 作为从机；
5. **多主控 / 热备**：一个网段一个安全码对应一台主控（多主控共存仅表现为候选列表）；
6. **键鼠以外的设备共享**：不支持 USB 外设（手柄、数位板等）转发（P3+ 再议）。

## 7. 关键约束与依赖

| 约束 | 说明 |
| --- | --- |
| C-1 | UI 框架固定为 gpui（用户决策）；其平台支持矩阵决定了 UI 层的兼容范围，见 [05-platform.md](05-platform.md) |
| C-2 | Wayland 安全模型不允许全局输入钩子，输入捕获/注入必须走 portal（InputCapture / RemoteDesktop）或 uinput 路径，能力按 compositor 矩阵降级，见 [05-platform.md](05-platform.md) |
| C-3 | macOS 辅助功能权限（Accessibility）是主控模式硬前提；安装包需引导用户授予 |
| C-4 | Windows 防火墙首次监听会弹授权，安装器应预配置入站规则 |

## 8. 需求追踪

规范实现期间，所有 PR / 任务需引用需求编号（如 `feat(proto): FR-5.2 UDP probe`）。验收以本文 AC 为准；AC 变更需先改本文并提升版本号。
