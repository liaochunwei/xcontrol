# 06 · UI 与系统托盘规范

> 状态：草案 v0.1 · 实现 FR-6.x。基于 2026-11 的 gpui 生态调研（结论摘要见附录 A；ADR-0001 记录选型决策）。

## 1. 技术选型（结论）

| 项 | 决策 |
| --- | --- |
| UI 框架 | **gpui**，经 `gpui-kit = "0.9"` 使用（其 re-export gpui API 并锁定配套 `gpui-pre` 快照），不自写 gpui 依赖、不混用版本源 |
| 组件库 | gpui-kit（75+ 组件：Form/Input/Switch/List/Sidebar/Dialog/Notification 等，Longbridge 生产验证） |
| 系统托盘 | **`gpui-tray = "0.3"` 直连**（M0 spike 实测选定，ADR-0001）：`gpui-kit` feature 与 gpui-kit 0.9.1 统一到同一 `gpui-pre 0.3.12` 版本源（类型共享），菜单为原生 GPUI `MenuItem` + action 分发（无需自建 TrayCommand channel）；其 Linux 后端走 zbus SNI 无 GTK，符合红线。原"Ropy 模式自建"（tray-icon/ksni + channel）降级为备胎；`xcontrol-tray` 收敛为核心状态快照 → 图标/菜单投影的适配层，不含平台胶水。证据：`docs/spike-tray/EVIDENCE.md` §B |
| 后台常驻 | `QuitMode::Explicit` ✔ 已验证（gpui-pre 0.3.12 含该 API；macOS 实测关全部窗口后进程持续存活，心跳日志见 `docs/spike-tray/EVIDENCE.md` §A）。附带约束：gpui-pre 0.3.12 需 **Rust stable（1.99.1 实测）**，1.92/1.95 编译失败（见 EVIDENCE §A0）——主 workspace 工具链锁定已随本结论修订为 1.99（2026-11-16，rust-toolchain/CI/docs/01 §6/docs/08 §2/clippy msrv 同步） |
| License | gpui / gpui-kit / gpui-tray 均 Apache-2.0 或 MIT，兼容任意授权 |

**红线**：Linux 上禁止引入任何依赖 GTK 主循环的托盘方案（与 gpui 自建事件循环冲突）；所有 UI 与托盘代码必须使用同一 gpui 版本源（Rust 类型共享）。

## 2. 应用形态

- **单进程**：`xcontrol`（`xcontrol-app` 产出）＝ gpui `Application` + 托盘 + 无头核心服务。核心逻辑运行在 tokio 运行时，与 gpui 主线程通过消息通道交互（见 [01-architecture.md](01-architecture.md) 线程模型）。
- **窗口管理**：
  - 启动 → 托盘就绪；设置窗口默认不自动弹出（首次运行向导除外）。
  - `QuitMode::Explicit`：关闭设置窗口不退出进程；仅托盘菜单"退出"退出。
  - `on_reopen()`（macOS Dock / 再次拉起）：打开设置窗口；Linux/Windows 二次启动进程时通过单实例锁 + IPC（本地 socket）唤起已有实例窗口。
  - Wayland 限制：托盘点击唤起窗口**不保证获得焦点**（xdg-activation 由 compositor 决定），设计上 best-effort：窗口已开则展示，未开则新建；不承诺置顶抢焦。
- **headless 模式**（FR-6.4，11-19-m6-security 裁定）：`xcontrol-app --headless` = **运行时无 UI 而非编译面分离**——跳过窗口/托盘/gpui Application 初始化（`run_window`/`run_headless` 均不进入），纯 tokio 会话运行时 + 日志；`--auto-quit-ms` 到点干净退出，`xcontrol-cli --status` 为只读查询配套。裁定依据：gpui 是 xcontrol-app 的硬依赖（ADR-0001 单一版本源），feature 化需门控整个 ui/tray 面、收益不成比例；docs/06 §2 原文"Application::headless() 或纯无 gpui 路径（xcontrol-cli）"中的**编译面分离语义留给 xcontrol-cli**（其依赖树无 gpui，NFR-4"headless 从机不限平台"的终极形态；当前 cli 仅承载 --status，host/client 运行时复用需先抽 session_rt 出 app——M6 裁定暂不拆）。headless 下向导不可用（无 UI 输入面）：需既有 config 或 `--code`。实测：无 DISPLAY/WAYLAND_DISPLAY 环境运行 + 干净退出（日志证据）；远端 Linux（lsdark-eos）实测配方 `cargo run -p xcontrol-app -- --headless --host --code test-code --auto-quit-ms 5000`，本次远端不可达、移交复跑。

**角色过滤（11-21 实测反馈裁定）**：设置里不放角色切换控件（托盘菜单已有）——
侧栏页集合按 `AppState.role` 快照过滤（托盘切换角色后随快照 ≤1s 重排；当前页
因切换不可见时回落状态页）：

| 页面 | 主控（Host） | 工作机（Client） | 依据 |
| --- | :-: | :-: | --- |

| 按键映射 | — | ✓ | 映射引擎在工作机侧生效（FR-3.x，docs/03 §4） |
| 全局热键 | ✓ | — | 切换/回主控是主控动作（FR-2.5） |
| 剪贴板 / 通用 / 日志 / 关于 | ✓ | ✓ | 应用级 |

> M6 现状：连接页未实装，白名单编辑先由**首次运行向导第 3 步**承载
> （allowlist 输入，与 CIDR 同套校验）；独立连接页仍属后续打磨。

> 映射页数据流（11-21 实测反馈）：预设选择 → 选择器从 `preset_rules` 反解填充；
> 用户改动任一选择器 → `preset = "none"` + 5 行选择器重建形态 2 修饰键规则
> （左右手成对）写入 config.rules（其余形态规则保留）——规则引擎/配置模型零改动。
> 术语（11-21）：用户可见文案「从机」→「工作机」（en = client）；内部标识
> （role="client"、日志 target、代码 slave 命名）不改。

交互规范：

- 配置修改**即时生效并持久化**（写 TOML，`xcontrol-config` 负责），无需"保存"按钮；破坏性操作（改安全码）弹确认。角色切换**只走托盘菜单**（FR-1.1；11-21 实测反馈：设置页无角色切换控件，托盘 SwitchRole 直下发不经确认模态）。
- 连接状态变化 ≤1s 反映到状态页与托盘（FR-6.1 AC）。
- 权限缺失（macOS 辅助功能 / Windows 防火墙 / Linux uinput 组）：状态页与托盘 tooltip 显示**可点击的修复指引**，点击跳转系统设置或打开引导文档。
- 所有表单校验失败就地提示（gpui-kit Form 校验），禁止静默吞错。

### 4.1 生效时点表（11-18-m4-ui 裁定，docs/01 §5 热加载缺口的最小钩子）

设置页改动 → `config.toml` 落盘（`xcontrol_config::save`）→ `CoreCommand::RuntimeConfigUpdate(Config)`（命令通道，FIFO）→ 运行时各消费点按字段分级生效。**不做文件监听**。

| 字段 | 生效时点 | 生效机制 |
| --- | --- | --- |
| `general.log_level` | **立即** | 消费点直接调 `logging::set_level`（`tracing_subscriber::reload` 句柄重建 EnvFilter 全局指令；XCONTROL_LOG 追加指令保留） |
| `hotkeys`（四键组合） | **立即**（11-21 反馈 3；原"下会话"） | 消费点写入共享单元后编译新 `HotkeySet` 并原位热替换运行中会话的全部检测面（`apply_hot_key_configs`）：从机注入前过滤 sink（全平台）+ mac 主控捕获流 `HotkeyFilter` + win/x11 平台注册源（`PlatformHotkeySource::update` 重建注册——被动捕获架构 mac/Linux 无重注册需求）。编译失败保留旧表 + 告警（下会话构造点重试）；无活动会话时下会话构造点生效。替换语义：修饰键跟踪与旧命中吞尾保留（防无 Down 的孤立注入），新表即时参与判定 |
| `keymap`（预设/直通/规则） | **立即**（11-21 反馈 4；原"下会话"） | 会话内 `RuntimeConfigUpdate` 消费点调 `MappingSink::set_rules`（`MappingEngine::set_rules`）：编译新规则整体替换（失败保持旧规则 + 告警）。origin 对照表/引用计数/组合级 pending 保留——已注入 OS 的修饰键释放按 origin 换算不卡键；新规则只影响其后的新按下判定。无活动会话时下会话构造点（`SessionConfigs`）生效 |
| `[layout]`（屏幕条目，FR-1.3） | **主控会话内即时**（重装配 + 重新下发 `CtrlMsg::Layout`，11-19-m5-layout） | 会话内 `RuntimeConfigUpdate` 消费点调 `layout_rt::rebuild_and_publish`：重装配全局布局（协商完成后有对端元数据；未协商空动作，握手时按会话快照装配）+ `PublishLayout` 出站；从机收帧经 `LayoutReceived` 安装 ScreenId → 本机屏映射表。切换目标序（热键/托盘）随之刷新 |
| `clipboard` | 下会话 | 会话构造点读最新值；剪贴板管线随会话重建生效 |
| `role`（向导完成/托盘切换） | 立即 | 向导完成 = `RuntimeConfigUpdate`——**等待相**（首次运行，无码启动）supervisor 即按 config.role 定角色退出等待相（不叠加 `SwitchRole`，双命令会二次翻转）；非等待相完成且角色不一致时补发 `SwitchRole`（FIFO 保序）。托盘切换已有路径不变 |
| `net.port` / `net.cidrs` / `net.discovery` / `net.allowlist` | 空闲重建时 | 无活动会话时 `RuntimeConfigUpdate` 触发 supervisor 循环重建（监听/发现循环按新值重启，通告器随重建重启）；会话中则等待下次重建。主控侧重建判定关注端口、发现层开关与白名单（serve 层白名单表 listen 时解析固定，FR-5.4——变更需重新绑定），从机发现循环判定整段 net；CIDR 仅从机发现消费，手动直连路径地址来自 CLI、不参与判定 |
| `net.confirmed_host`（FR-5.5） | 下一轮发现扫描 | 状态页「连接并记住」按钮 / 托盘候选子菜单：`ConfirmHost` 命令**进程内立即**（发现循环跳过剩余退避按确认目标直连）+ 状态页路径经 `commit_config` 落盘；落盘值随 `RuntimeConfigUpdate` 传播，发现循环每轮读共享单元最新值。托盘路径只进程内生效（下次启动回退自动语义） |
| 自启开关 | 立即 | UI/托盘 action 直接调 `Autostart` trait（OS 级配置，不经核心命令；11-18-m4-tray 先例） |
| `security_code_ref` + 安全码 | 立即（会话断开） | **换码协议（docs/07 §3.3，11-19-m6-security 实装）**：码经 SecretStore 落盘（keychain 可用走钥匙串，否则 file 0600；config 落盘失败回滚 store——双故障收口）、ref 更新进 config；`RuntimeConfigUpdate` 消费点检测引用变化 → 会话内立即 Quit 断开、空闲循环上抛 ConfigReload → supervisor 按新引用重读 SecretStore + 重派生 PSK；发现循环 `PskCache` 属循环局部，重建即失效。对端将见会话断开，需用新码重新配对 |

UX 呈现（docs/06 §4「无保存按钮」约束下的诚实提示）：改动生效时于页内日志区记录 `app::settings` 条目（热键/映射为"即时生效"），状态页日志可查；不做每字段徽标（M6 打磨）。

单实例（docs/06 §2 M4 最小裁定）：窗口模式启动时对本机 `net.port` 做 TCP connect 探测（500ms 超时）；连上即判定已有实例，记 warn 日志后照常运行（既有实例的握手失败观测面会多一次来源 127.0.0.1 的折叠事件——可接受噪音；不用 bind 探测：macOS std TcpListener 默认 SO_REUSEADDR，恒假阴性）。已有实例的窗口唤起仅 mac on_reopen 已有；锁 + IPC 移交 M5/M6。

## 5. 托盘规范（FR-6.1）

### 5.1 图标状态机

```
主控: [在线(N≥1)] [搜索中(0)] [暂停] [错误]      工作机: [已连接] [搜索中] [暂停] [错误]
```

- 图标资源内嵌（SVG 源 → 各平台 PNG/模板图），macOS 用 Template Image 适配深浅色；状态用角标（N 台在线 / 感叹号）。
  **M4 实现裁定（11-18-m4-tray）**：图标收敛为 **2 张程序化生成的模板图**（常态 = 环形加中心点、错误 = 环形加感叹号，macOS template + 2x；其余平台固定色）；搜索中/暂停由 tooltip 与角标表达，多态预渲染图标（SVG 源管线 → 状态全覆盖）移交 M6 打磨。
- **应用图标（2026-11-24，macOS 打包）**：`.app` 带应用图标——此前 bundle 从未包含图标，Finder / Dock 显示系统默认空白图标（用户反馈补齐）。图形与托盘常态图标**同源**（环形加中心点、品牌蓝）：`scripts/macos/icon.swift` 按 macOS 图标网格绘制（圆角方块占画布 824/1024、圆角半径为边长的 22.37%；图形盒占方块边长 68%，环外径 0.44 / 内径 0.30 / 中心点 0.10——比例与 `xcontrol-tray` 的 `draw()` 一致），`scripts/macos/icon.sh` 合成入库产物 `scripts/macos/AppIcon.icns`（iconset 全部 10 个尺寸），`scripts/macos/dmg.sh` 拷进 `Contents/Resources` 并以 `CFBundleIconFile` 引用（[10-install.md](10-install.md) §1.1）。**打包不依赖 swift**，只读取入库的 `.icns`；托盘图标改了要同步重跑 `icon.sh` 并提交新的 `.icns`。安装后 Finder 与 Dock 显示图标属实机验收项（任务 11-24 的 AC12）。
- 悬停 tooltip：`XControl · 主控 · 2 台在线 · 延迟 8ms`（延迟段仅在线态且有指标时附加；M4 会话快照无 RTT 指标——段位支持已就绪，指标聚合 M5 接入）。
- 图标更新只由"核心服务状态快照"驱动（避免 UI 层各自拉取造成状态漂移）。

```
退出
```

- 菜单事件流（M0 spike 定稿）：`gpui-tray` 原生 `MenuItem` + action 分发，事件直接落在 GPUI executor 主线程，action 处理器经 `CoreHandle` 调用核心服务 API（无需自建 channel 桥接）。禁止在 action 处理器外触碰核心状态。Ropy 备胎路径（平台回调 → `TrayCommand` 枚举 → channel → executor）仅在 gpui-tray 不可用时启用（ADR-0001）。
- Linux（gpui-tray 的 zbus SNI 后端）：菜单为 DBusMenu 描述性导出（无原生控件），不支持的项（复选框动画等）做降级：用 `●`/`○` 前缀文本表达勾选态。

## 6. 状态与数据流（UI ↔ 核心）

- 单一事实源：核心服务暴露 `AppState` 快照流（watch channel，200ms 合并更新节流）＋ 命令入口 `CoreHandle`。
- UI 是**纯投影**：不持有连接/会话状态，仅渲染快照；所有变更走命令（含乐观更新回滚）。
- UI 严禁直接触碰网络/平台输入层（分层红线，见 [08-engineering.md](08-engineering.md)）。
- 指标（延迟/事件速率）经核心聚合，UI 每 500ms 拉取快照刷新，避免高频重绘。

## 7. 可用性与无障碍

- 键盘可达：设置窗口所有操作可 Tab/Enter 完成（gpui AccessKit）。
- 深浅色主题跟随系统；文本不使用纯色对比 < 4.5:1 的组合。
- i18n（FR-6.5，11-19-m6-release 落地）：`xcontrol-i18n` 轻量文案表框架（零依赖 static table，`tr("menu.pause")` + `trf(key, args)` 占位替换），zh-CN 完整 + en 全量（两表一致性由 parity 测试钉死）。**范围裁定**：gpui UI 层（设置页/向导/确认模态/窗口标题）与托盘（菜单/状态头/tooltip）key 化；错误信息（thiserror Display）、tracing 日志与 CLI `--status` 输出 v1 保持中文单语（双语化成本不成比例——en 覆盖 UI 层即满足 FR-6.5「UI 多语言」，audit 报告见任务记录）。语言选择 = config `[general].language`（zh-CN 默认 | en），设置 → 通用页下拉切换：落盘 → `RuntimeConfigUpdate` 消费点 `set_language`（与 log_level 同点）即时生效——静态文案随下一次渲染切换（托盘 ≤1s 随 200ms 刷新循环），控件构造期快照（输入框占位/下拉选项）在下个窗口生命周期对齐（v1 边界，诚实呈现）。
- 首次运行向导的权限页按平台条件渲染，附"复制诊断信息"按钮。

## 8. M0 托盘 Spike（验收清单）

1. `gpui-pre`（gpui-kit 0.9.x 锁定版本）含 `QuitMode::Explicit`：关全部窗口后进程存活 ✔（macOS 实测通过；附带发现工具链需 stable ≥1.99，1.92/1.95 编译失败——证据 `docs/spike-tray/EVIDENCE.md` §A/§A0）
2. `gpui-tray` 的 `gpui-kit` feature 与 gpui-kit 0.9.x 类型兼容（编译通过 + 托盘出现）✔（统一到 gpui-pre 0.3.12 单一版本源；菜单事件经 osascript 真实点击 ×3 全部回传 GPUI executor——EVIDENCE §B）
3. 若 2 ✘：Ropy 模式三平台 demo（tray-icon mac/win + ksni linux + channel → executor）—（不适用：2 已通过，按 PRD 未触发；自建方案归档为备胎，见 ADR-0001 更新记录）
4. Wayland 合成器（GNOME/KDE/sway）下托盘图标 + 菜单渲染正常 未实测（spike 本机为 macOS、无 Linux 桌面；Linux 侧为编译级结论外推，已列 ADR-0001 跟踪项）
5. 结论写入 ADR-0001 并更新本文 §1 表格 ✔（2026-11-16 完成，见 ADR-0001 更新记录）
