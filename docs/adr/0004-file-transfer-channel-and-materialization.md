# ADR-0004：跨设备文件传输的通道拓扑与物化策略

- 状态：已接受
- 日期：2026-11-26
- 关联需求：FR-7.3（跨设备文件复制粘贴）；上游预留 FR-7.1/7.2、NFR-9
- 关联任务：11-26-file-transfer（父）/ 11-26-file-transfer-spec

## 背景

FR-7.3 的目标体验是「像本地一样复制文件」：A 机复制，B 机粘贴时才真正传输
（复制瞬间仅同步元数据清单）。docs/00 §4.7 对 FR-7.1/7.2 只预留了"复用 v1 分块
传输通道"的方向，未定通道拓扑与接收端物化机制；本 ADR 在开工前补上这两个决策
（docs/00 §4.7 要求"实现方式届时以 ADR 决定"）。

约束与事实：

1. docs/02 §4.4 已有实测教训（2026-11-21 修订）：大块数据与控制帧同连接会队头
   阻塞，断连即控制被切回主控——文件传输是比剪贴板图片更大的块（GB 级可能），
   必须独立于控制面。
2. 现有剪贴板通道状态机（docs/02 §6）按"剪贴板内容"语义定参：16MiB 上限、
   单活动 clip、10s 固定超时、"允许失败不重传"。文件语义与此冲突：总量 GB 级、
   时长分钟级、失败必须可感知可重试（用户在粘贴处等待）。
3. 源端"复制"天然是元数据操作：OS 剪贴板里只有路径引用，文件在文件系统不动。
   惰性传输的复杂度集中在接收端"粘贴物化"。
4. docs/04 §3 否决过"拉模式"，但其理由（源应用可能清板、源可能退出受控态）只
   适用于剪贴板内容字节；文件持久在文件系统、XControl 常驻，拉取时机后置到
   粘贴不引入新的时序脆弱面（源离线即条目级错误，不重试风暴）。

## 备选方案

**通道拓扑：**

| 备选 | 放弃原因 |
| --- | --- |
| 复用剪贴板 TCP（同连接加新 kind） | 一个连接承担两套重组状态机（clip 的 16MiB/单活动/10s 语义 ≠ 文件的 GB 级/并发/可重试语义）；文件长流与剪贴板同步互为队头阻塞 |
| 控制连接上复用 | §4.4 实测教训直接否决——大块数据必须独立连接；1.0 期的同连接裁定已被 2026-11-21 修订取代，不再回头 |
| **独立第三条 TCP（选定）** | 与双连接模型同构：另拨 TCP → 独立 Noise 握手 → 首帧绑定会话；故障隔离面最清晰，每对机器至多 3 条连接，均按需建立、空闲关闭 |

**接收端物化机制：**

| 备选 | 放弃原因 |
| --- | --- |
| OS 原生惰性（mac `NSFilePromiseReceiver` / win `CFSTR_FILEDESCRIPTOR+FILECONTENTS`） | 平台能力不对称（Linux 无对应机制）；mac 粘贴路径的 promise 支持未经实机验证；win 虚拟文件需 STA OLE 服务端，复杂度高。列为 P2 增强，不作为 v1 前提 |
| **统一 stage-then-mount（选定）** | 三平台行为一致：拉流落盘暂存区 → 把真实文件引用写上系统剪贴板 → 注入粘贴键。粘贴键本就是 XControl 注入的（KVM 架构天然钩子），拦截自身注入路径即可，零系统级 hook。代价：粘贴延迟 = 传输时长（进度 UI 缓解，切片 d） |

## 决策

1. **通道**：文件传输走独立第三条 TCP（file 通道），与 §4.4 剪贴板通道同构——
   完整 Noise 握手，首帧 `FileBind { session_id }` 绑定控制会话；按需建立、
   空闲关闭；通道任何故障只影响文件域，独立退避重连。消息域 kind 0x58–0x5F，
   随 XCP minor 1.2 引入（1.1 对端"未知 kind 跳过"无损降级）。
2. **物化**：接收端统一 stage-then-mount（落盘暂存 → 挂真实文件引用 → 注入
   粘贴）；透明粘贴路径（拦截自身注入的粘贴键）为默认体验，托盘显式动作作为
   兜底入口。
3. **安全不变量**：拉取请求只含 `transfer_id + 条目索引 + offset`，绝不携带
   路径——源端只服务"本会话已通告清单"的条目，杜绝对端构造请求读取任意文件。
4. **哈希与超时**：blake3 源端边流边算（复制瞬间不预哈希）；超时改"分块空闲
   超时 + 总时长上限"，不用固定 10s。

## 后果

正面：

- 文件面故障与剪贴板/控制面完全隔离，复用已实测的双连接隔离语义。
- 三平台物化路径统一，实现与测试面最小；协议只增 kind，1.1 对端无损降级。

代价与跟踪项：

- 每对机器至多 3 条 TCP（连接管理复杂度 +1，可接受——均按需建立）。
- 粘贴延迟 = 传输时长，进度/取消 UI 必须到位（切片 d）。
- 物化挂板后的回环指纹需要新规范形（名字+大小，不含 mtime/绝对路径），
  docs/04 §8 落点。
- 待实机复核（docs/05 §8）：mac Finder 复制文件粘贴进文本应用的行为；
  `NSFilePromiseReceiver` 在粘贴路径的支持程度（P2 增强的前置 spike）；
  Windows `CF_HDROP` 长路径/Unicode 写入。
